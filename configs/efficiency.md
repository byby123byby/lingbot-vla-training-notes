# 独立训练时怎样减少时间与 GPU 浪费

决定：从官方基座独立训练自己的模型，不接队友权重。后续续训只使用本项目自己产出的 checkpoint。本页是计划，不是已执行训练或提分结果。

## 直接采用的做法

1. **把 CPU 准备放到付费训练窗口之前。** 本地先整理数据选择、配置、清单和恢复步骤；能在已有 CPU 环境完成的转换和统计尽量提前完成。最终 LingBot norm_stats 已在 CPU 上按官方特征映射、动作块和末尾填充统计；统计文件及校验报告已保存。
2. **使用已有全参数路线。** AdamW、FSDP2 full-shard、完整 teacher、micro batch 16、global batch 256。参考文档说明 Muon 会增加训练时间，本轮不额外引入它。
3. **把一次预算看作自己的一个训练段。** 保存模型、优化器、调度器、步数与数据加载状态，下次承接自己的状态，避免重复基座适配。当前 HF 续训模板是重新初始化优化器的模板，不是精确 DCP 恢复入口；完整状态恢复入口已补齐为 run_budgeted.py --resume；GPU 恢复仍未实测，不承诺数据 worker 的随机序列逐位复现。
4. **压缩非训练占用。** 本轮不安排万回合评测、不生成额外仿真轨迹，训练不录视频；配置只在本段末尾保存一次完整 DCP。必须保留保存和销毁窗口，而不是把云端所有时间都算成可训练时间。
5. **优先用增强改善观测覆盖。** 采用已公开的图像增广方向，不改变动作与语义。强增广已通过固定版本补丁接入，并完成 CPU 重放和 teacher 对齐检查；需要先安装补丁，原始颜色开关本身不会自动产生强增广。

## 不直接采用的捷径

- 不为省钱使用队友模型或官方 RoboTwin 专项后训练权重作为自己的训练起点。
- 不把 batch 降低后“step 更多”当作看过更多样本或质量更高；比较时应固定有效 batch 和数据量口径。
- 不只启用八卡实例中的一两张卡以为能省 credits，实例费用按所租规格计算。
- 不为了速度关闭 depth/video teacher 或切回 LoRA；当前选择仍按已采纳的全参数经验执行。
- 不把更高 worker 数、编译、no-reshard 等未测配置承诺成免费加速。本轮不花额外算力做调参验证。

## 预算能做到哪里

保守可用 30 credits；当前八卡实例安排 24 credits / 3 个计费小时，约 2 小时净训练窗口。按参考速度，250 步约 103 分钟，额外开销可能降低实际完成步数。它是自己的第一段训练，不是可宣称已经收敛的高分模型。

想达到公开记录的 20k 量级，需要后续持续增加训练总量，或未来有明确的更高效可用方案；没有证据支持把同等训练效果压缩到当前几百步。当前账户没有四卡入口，不能把四卡七小时方案当作现在能执行的选项。
